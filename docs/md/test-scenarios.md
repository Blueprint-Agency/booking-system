# Scenario Inventory

Every acceptance scenario the product promises, one row each, with the test that proves it. This
table answers "how far have we tested?". How to add a row and how to name a test with its ID:
`testing.md` § Scenario Inventory. Check it with `node scripts/check-scenarios.mjs`.

Drafted from `prd.md` (user journeys, roles, cross-cutting rules, notifications),
`fe-client-features.md`, `admin-restructure.md`, `class-booking-lifecycle.md` (with
`spec-pre-launch-batch.md` §1–§3), `pt-session-lifecycle.md`, `spec-finance.md`,
`spec-credit-ledger-payroll.md`, `spec-instructor-leave.md`, `spec-instructor-leave-pools.md` and
`spec-instructor-leave-remediation.md`. Each scenario ends with its sources in italics. Where a doc
and today's code disagree, the row states what the code does. A row starting **Not built.** is a
promise whose route still answers `501`.

**IDs are stable.** Never renumber or reuse one. A new row takes the next number in its area; a
dropped scenario stays, marked `wont-test`, with the reason in its cell.

## Columns

- **ID** — area prefix and number, e.g. `CHK-03`.
- **area** — the prefix, one of:
  `AUTH` sign-up, login, verification, password reset ·
  `WVR` waivers ·
  `CAT` public catalogue & marketing pages ·
  `BKG` class booking ·
  `WTL` waitlist ·
  `CXL` class cancellation & cancellation policy ·
  `CHK` check-in & per-booking QR ·
  `ROS` roster & session detail ·
  `SCH` schedule, class instances, series, capacity, rooms, class types ·
  `WSP` workshops ·
  `PT` private sessions & PT requests ·
  `PKG` packages, validity, Families, promotions ·
  `CRD` credit ledger ·
  `PAY` checkout & payments ·
  `RFD` refunds ·
  `PRM` promo codes ·
  `MRC` merch ·
  `CORP` corporate ·
  `REF` referral ·
  `INV` member invoices & purchases ·
  `ACC` member account ·
  `CUS` admin customers ·
  `STF` staff, roles & invitations ·
  `LOC` locations & workspaces ·
  `NTF` notifications & email templates ·
  `INB` inbox ·
  `FIN` finance ·
  `PAYR` payroll ·
  `LEV` instructor leave ·
  `RPT` reports ·
  `SUP` super portal ·
  `TEN` Tenant isolation ·
  `AUD` audit trail
  An area with no rows yet (`REF`, `INV`, `RPT`: their routes are unbuilt or the specs defer them)
  has no section.
- **role** — whose action it is: `member` (including an anonymous visitor), `instructor`, `admin`,
  `super`, or `system` (a scheduled job, a webhook, or a rule with no human actor).
- **scenario** — **Given** / **When** / **Then**, then _(sources)_.
- **risk** — the worst outcome if it breaks: `money`, `tenancy`, `data-loss` or `UX`.
- **level** — the lowest level that can prove it: `unit`, `integration` (HTTP or service against
  real Postgres) or `e2e` (a real browser).
- **covered by** — the test file(s) with a test named with this ID, comma-separated.
- **status** — `uncovered`, `covered`, `failing` (the test exists and is red) or `wont-test`.
